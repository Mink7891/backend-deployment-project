# Работа двух участников

ФИО и фактические коммиты заполните перед сдачей. Распределение ниже — план,
а не заявление о выполненном вкладе.

| Участник | Основная работа | Что показать на защите |
| --- | --- | --- |
| Участник 1 | Domain и Use Cases, API, модели и миграции, CheapShark/mock, бизнес-тесты | Поиск → wishlist → порог → журнал; устройство Use Case и транзакции |
| Участник 2 | Docker/Compose, Jenkins, мониторинг, JMeter/gate, Trivy, backup/restore | Деплой, графики, нагрузку, restore и rollback |

Оба проверяют пользовательский сценарий, API-документацию и итоговый Word-отчёт.
Каждый должен понимать общую схему и уметь провести небольшое изменение через
pipeline. На защите одного знания своей папки недостаточно.

Практический порядок:

1. Согласовать API и Use Cases, проверить локальный mock-сценарий.
2. Участнику 1 довести backend и проверку бизнес-правил; участнику 2 поднять
   инфраструктуру на двух машинах и настроить credentials.
3. Вместе выполнить деплой, реальный CheapShark-запрос и нагрузку через mock.
4. Зафиксировать результаты, устранить проблемы, показать restore и rollback.
5. Разделить заполнение отчёта по зонам ответственности, затем вместе проверить
   ссылки, скриншоты, соответствие commit SHA и отсутствие секретов.

Не приписывайте одному участнику автоматически весь код его зоны. В отчёте
отразите реально выполненную работу и изменения каждого.

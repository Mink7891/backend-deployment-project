Проверки выполнены на одном Windows-компьютере через Docker Desktop с Linux-контейнерами.
Это подтверждает локальную работоспособность реализации. Двухмашинный Jenkins pipeline,
push/pull образа из реестра, откат между тегами коммитов и полное нагрузочное испытание
для защиты ещё предстоит выполнить по [чек-листу](requirements-checklist.md).

## Демонстрация через Swagger и Grafana

При пользователе выполнены запросы в Swagger: без ключа получен 401;
создание списка «Демонстрация БСМО-31-25» вернуло 201. Добавлена LEGO Batman
с `steam_only=true` и порогом `4.00`: цена Steam `3.99`, порог достигнут.
Сводка вернула 200, один элемент, одно совпадение и сумму `3.99 USD`.
Повторный refresh вернул `notifications_created=0`, в журнале осталось одно событие.
История цен вернулась из PostgreSQL с `source=mock`.

Повторное добавление той же игры получило 409, отрицательный `target_price=-1.00`
получил 422 с указанием `body.target_price`. Демо-список с ID 4 после проверки
удалён: DELETE 204, последующий GET 404. Остальные списки не удалялись.

В отдельном видимом PowerShell-окне повторены pytest и Ruff: **59 passed**,
lint и проверка форматирования завершились с кодом 0. Предупреждение pytest
о недоступном каталоге кэша не повлияло на выполнение тестов.
В Grafana показаны запросы, задержки, доля 5xx и готовность API/БД.
Снимок отражает ручную демонстрацию, а не нагрузочное испытание.
Безопасные скриншоты включены в `GameRadar-report.docx`.

API-ключ, попавший в блок Curl при демонстрации, заменён в локальных `.env`
и `.env.load`. App и worker пересозданы с тем же образом; семь сервисов healthy.
Проверено: старый ключ получает 401, новый ключ 200, `/health` 200.
Для дальнейших запросов в Swagger нужно заново авторизоваться ключом из `.env`.

## Короткая проверка JMeter

JMeter **5.6.3** выполнен в non-GUI режиме на отдельном проекте `game-radar-load`
с БД `radar_load`, mock в API и worker и собственным мониторингом.
Параметры: `threads=2`, `steps=3`, `ramp=1`, `hold_seconds=5`,
`duration=16`, `think_ms=100`. Проверены четыре операции и JSON assertions;
в тестовой БД появились шесть wishlist и шесть элементов.

| Метрика | Значение |
| --- | ---: |
| Запросов | 333 |
| Ошибок | 0 (0%) |
| Пропускная способность по JTL | 21.207 запроса/с |
| p90 | 20 мс |
| p95 | 24 мс |
| p99 | 2644 мс |

Gate `errors <= 1%`, `p95 <= 1000 ms` прошёл. Первые запросы групп стартовали
примерно на 0, 5 и 10 секунде. У четырёх первых подключений JTL зафиксировал
TCP Connect от 2617 до 8038 мс; этот факт учитывается в p99 и требует отдельного
анализа при полноценном испытании. Короткий запуск проверяет план и assertions;
он не определяет точку насыщения или производительность на учебных VM.

Прогон выполнен до обновления базового образа; бизнес-код тот же. Финальный образ
отдельно прошёл запуск, smoke и проверку PostgreSQL-миграций. Для защиты нужен
новый полный прогон с финальным тегом коммита на двух разных машинах.

JTL и HTML доступны локально в `load-tests/results/local-smoke/`, JSON summary
и экспорт мониторинга — в `.local/reports/`. Эти каталоги исключены из Git.
Временные контейнеры и тома нагрузочного проекта после экспорта удалены.
